## P0. Каркас бэкенда

### R-01. Разобрать FastAPI на модули без смены поведения

**Статус.** Выполнено.

**Зачем.** Маршруты, Pydantic-модели, проверка токена и валидация звонков жили в одном `backend/app/main.py`. На такой файл нельзя наращивать пользователей и CRUD шаблона.

**Сейчас.** HTTP разрезан на роутеры `info`, `schedule`, `bells`, `admin`. Сборка приложения — `main.py` (`uvicorn app.main:app`). Модели — `schemas.py`, токен — `security.py`, UTF-8 JSON и общие проверки — `http.py`. CRUD — в `db.py`, DDL — пронумерованные sql в `app/migrations/versions/` (R-02). Роутера `auth` ещё нет (P2). Роутера ботов и исходящего webhook нет.

**Сделать.** —

**Не входит.** Новые ручки, миграции как продукт (это R-02), смена словаря недели (R-03), авторизация (P2).

**Готово когда.** `uvicorn app.main:app` как раньше; живой `/docs` FastAPI показывает те же операции; фронт не трогаем.

**Зависит от.** —

### R-02. Миграции схемы SQLite

**Статус.** Выполнено.

**Зачем.** Пользователи, сетки звонков по дням, аудит — новые таблицы. Раньше новые `CREATE` появлялись при коннекте, старые колонки не конвертировались ([architecture/Развёртывание](../architecture/Развёртывание.md)). На проде файл `./backend/data/schedule.db` переживает пересборку образа.

**Сейчас.** Табличный versioner: `schema_migrations` + sql в `backend/app/migrations/versions/`. Базовая миграция `001_initial.sql` — схема as-is. `connect()` / `init_db()` применяют непрогнанные шаги. Команда: `python -m app.migrate` (локально ещё `make migrate`; в контейнере `docker compose exec backend python -m app.migrate`). Alembic нет.

**Сделать.** —

**Не входит.** Сами новые сущности (они приедут своими задачами поверх мигратора).

**Готово когда.** Пустая БД и уже существующий `schedule.db` поднимаются одной командой; повторный запуск миграций идемпотентен.

**Зависит от.** R-01 желателен (куда класть миграции), не жёсткий блокер.

## P1. Контракт данных

### R-03. Один контракт дня, недели и версии снимка

**Статус.** Выполнено.

**Зачем.** Клиент держал `odd`/`even`, сервер — `green`/`red`. Пары дня без `start`/`end`. `GET /api/info` считал неделю по локальной дате процесса. Текст в `lessons` мог не совпадать со справочником.

**Сейчас.** Цвет недели везде `green`/`red` (`all` — на обе). «Сегодня» и границы недели — `Europe/Moscow`. `GET /api/schedule/day` отдаёт слитый шаблон+overrides и слоты regular/short. `revision` (= `uploaded_at`) есть в info, шаблоне и дне. ФИО и кабинеты в уроках канонизируются так же, как в справочнике.

**Сделать.** —

**Не входит.** CRUD шаблона (P3), полные сетки пн/чт/куратор (P4), переписывание SW, исходящий webhook «что изменилось» (внешние сервисы сами опрашивают API).

**Готово когда.** Публичный клиент может показать день, почти не маппя поля. Нет `odd`/`even` в новом коде. Тесты на неделю около границы ISO и на дату в Москве.

**Зависит от.** R-01.

## P2. Безопасность и роли

Студенческий `/` без логина не закрываем. Закрываем ложную защиту админки и даём **вход преподавателя**. Первый сезон: пользователей заводит только главный администратор, саморегистрации нет.

### R-04. Учётные записи и роли

**Зачем.** В коде нет пользователей. «Админ UI» — PBKDF2-хэши в `frontend/js/config.js`. «Админ API» — заголовок `X-Admin-Token` со значением по умолчанию `dev`. Преподаватель на сайте неотличим от студента.

**Сейчас.** Таблицы `teachers` — справочник ФИО из Excel, не логины. Ролей в БД нет.

**Сделать.**

- Сущности: пользователь (login, хэш пароля **на сервере**, статус active/disabled), роль `admin` | `teacher`.
- Связь преподавателя с записью каталога (ФИО / id), чтобы потом фильтровать «мои пары».
- Bootstrap: из env создаётся **один** главный администратор, если пользователей ещё нет. `ADMIN_TOKEN` как вечный ключ API после этого не использовать.
- Пароли не логировать, не класть в git.

**Не входит.** Экран логина (R-05), форма «добавить преподавателя» (R-06), кабинет (R-07), CORS (R-08).

**Готово когда.** В БД можно создать admin и teacher; повторный старт приложения не затирает пользователей; без записи в БД мутаций нет.

**Зависит от.** R-02.

---

### R-05. Серверный вход вместо хэшей во фронте

**Зачем.** Экран `/admin/` обходится просмотром статики. Сессия в `sessionStorage` ничего не значит для API.

**Сделать.**

- `POST /api/auth/login` / `logout` / `me`. Сессия: httpOnly cookie или непрозрачный token, проверка на сервере.
- Админка и (позже) кабинет преподавателя ходят с этой сессией, не с `schedule_admin_token` в `localStorage`.
- Удалить `AUTH` salt/hash из клиентского `config.js` и клиентский PBKDF2 как источник правды.
- Блокировка после N неверных попыток — на сервере (сейчас счётчик в `localStorage`).

**Не входит.** Приглашения по ссылке, OAuth, 2FA.

**Готово когда.** Подмена фронта не даёт вызвать `PUT`/`POST` админки. Логин с верным паролем из БД открывает панель; неверный — 401.

**Зависит от.** R-04.

---

### R-06. Главный администратор выдаёт доступ

**Зачем.** «В первое время» без самозаписи и без внешней директории: админ заводит преподавателей руками.

**Сделать.** В админке раздел «Пользователи»: создать (логин, пароль или одноразовый), роль, привязка к ФИО из справочника, отключить. Только роль `admin`. Список без хэшей паролей.

**Не входит.** Приглашение на email, сброс пароля «забыл» самообслуживанием (админ задаёт новый пароль вручную — достаточно). Массовый импорт из Excel.

**Готово когда.** Админ создаёт преподавателя, тот проходит R-05; отключённый пользователь не входит. Студент по-прежнему смотрит `/` без учётки.

**Зависит от.** R-05, справочник преподавателей (достаточно текущего `GET /api/teachers`; CRUD каталога — R-19, не блокер).

---

### R-07. Вход преподавателя

**Зачем.** Минимальный осмысленный смысл роли `teacher`: не только «строка в БД», а вход в свой контур.

**Сделать.**

- Экран входа (общий с админом или `/login`). После входа роль решает, куда вести: admin → `/admin/`, teacher → кабинет.
- Кабинет преподавателя (минимум): пары, где он указан, на выбранную дату / неделю; те же слитые дни, что у студента (`resolve_day`), без Excel и без чужих мутаций.
- Публичный `/` не требует входа.

**Не входит.** Право преподавателя ставить замены (отдельное решение позже, не в этом бэклоге).

**Готово когда.** Заведённый в R-06 преподаватель логинится с телефона, видит свои пары офлайн-сети пока не нужен. Чужое расписание групп целиком в кабинете не обязательно (можно дать фильтр «мои»). Мутаций API у teacher нет.

**Зависит от.** R-06, R-03 (чтобы «мои пары» совпали с каноном ФИО).

---

### R-08. Ужесточение периметра

**Зачем.** Даже с сессией остаются CORS `*`, дефолтный `dev`, админка доступна с любого origin.

**Сделать.** CORS только origin сайта. На проде отказ стартовать с паролем/токеном по умолчанию. Cookie: Secure / SameSite по схеме деплоя. Rate limit на `/api/auth/login`. Не светить `/admin/` в публичном UI (как сейчас). Секреты только в env.

**Не входит.** WAF, отдельный IdP, mTLS.

**Готово когда.** С чужого origin мутации отклоняются; в README/доке деплоя явный чеклист секретов; `ADMIN_TOKEN=dev` на проде не проходит.

**Зависит от.** R-05 (чтобы было что защищать). Можно частично параллелить.

---

### R-09. Журнал аудита на сервере

**Зачем.** Сейчас `melmk_audit_v1` — лог браузера админа, его не видит второй админ и нельзя разобрать «кто снял пару».

**Сделать.** Писать на сервер: кто, когда, действие, сущность (группа, дата, пара, пользователь). Чтение — только admin. Клиентский audit как источник правды удалить.

**Не входит.** SIEM, бесконечное хранение, UI аналитики.

**Готово когда.** Замена пары и создание пользователя оставляют запись, переживающую смену браузера.

**Зависит от.** R-04, мутации уже идут под сессией (R-05). Имеет смысл закрывать по мере появления ручек P3–P5, но контракт таблицы — здесь.

## P3. Расписание вручную, Excel опционален

### R-10. Группы как сущность, не DISTINCT из уроков

**Зачем.** Список групп = уникальные `group_name` из `lessons`. Без Excel нельзя завести группу. После `replace_schedule` всё затирается.

**Сделать.** Таблица групп (код, активность). CRUD для admin. Публичный `GET /api/groups` читает её. Удаление: запрет или архив, если есть уроки — явно.

**Не входит.** Парсер Excel, редактор пар.

**Готово когда.** Админ создаёт `ТМ-999` без файла; студент видит её в пикере (пустой день — валидное состояние).

**Зависит от.** R-02, R-05.

---

### R-11. Ручной шаблон недели

**Зачем.** Редактор «Расписание» в админке пишет **overrides на календарную дату**, не сетку «каждый понедельник зелёной недели». Смена семестра = новый `.xlsx`.

**Сделать.** API и экран: для группы + дня недели + цвета недели задать пары 1–12 (предмет, преподаватель, кабинет, пусто = нет пары). Это запись в `lessons`, не в `lesson_overrides`. Overrides по-прежнему только на дату.

**Не входит.** Импорт файла (R-12), мастер замен на 16 недель (R-18).

**Готово когда.** Можно собрать семестр с нуля в админке; публичная неделя это показывает; Excel не обязателен.

**Зависит от.** R-10, R-03.

---

### R-12. Excel как импорт в ту же модель

**Зачем.** Официальная выгрузка колледжа останется. Она не должна быть единственным способом и не должна обходить ручную модель.

**Сделать.** `POST /api/admin/upload` заполняет группы (R-10) и шаблон (R-11). Режимы: заменить шаблон целиком / (если просто) только отсутствующие группы. Парсер `parser.py` остаётся каноном разбора заливки green/red. Ответ upload — diff: сколько групп/пар создано, warnings как сейчас.

**Не входит.** Локальный SheetJS-парсер как второй канон (R-14). Авто-очистка overrides — отдельное правило R-13.

**Готово когда.** Файл по-прежнему поднимает семестр; после ручных правок повторный импорт ведёт себя предсказуемо (см. R-13).

**Зависит от.** R-11.

---

### R-13. Политика замен при смене шаблона

**Зачем.** Повторный upload **не чистит** `lesson_overrides`. Старые отмены садятся на новые номера пар и врут студентам ([processes/Импорт Excel](../processes/Импорт Excel.md)).

**Сделать.** Явный выбор при импорте/смене семестра: оставить overrides / снять все будущие / снять все. Показать админу счётчик. Никакого молчаливого «оставили как было» без цифры.

**Не входит.** Умный матчинг «эта замена про того же преподавателя».

**Готово когда.** Админ не может залить новый семестр, не ответив на вопрос про замены; выбранное действие выполняется транзакцией.

**Зависит от.** R-12.

---

### R-14. Один путь разбора Excel — сервер

**Зачем.** Без токена админка кормит `.xlsx/.xls/.csv` в `frontend/js/parser/` (другая модель колонок) и пишет только IndexedDB. Студенты это не видят; админ думает, что «залил расписание».

**Сделать.** Убрать канонический локальный импорт сетки. Файл всегда уходит на API (нужна сессия admin). JSON-импорт как перенос **кэша** либо удалить, либо явно пометить «только это устройство». Клиентский парсер не развивать.

**Не входит.** Переписывать openpyxl-правила заливки.

**Готово когда.** В UI нет сценария «расписание только в этом браузере» как основного; документация процесса импорта совпадает с кодом.

**Зависит от.** R-12, R-05.

## P4. Звонки

### R-15. Сервер хранит все сетки МелМК

**Зачем.** API: одна `bell_regular` + short-даты. Клиент: `regular` / `monThu` / `thursday` / `shortDay` / `curator` в `localStorage`. «Сейчас» и вкладка «Звонки» живут с клиента; серверные слоты админка не сохраняет ([processes/Звонки](../processes/Звонки.md)).

**Сделать.** В БД: слоты по типу дня (обычный, пн, чт, сокращённый шаблон), кураторский час (пн/чт, вкл, время, подпись), список дат-исключений со своими слотами. Валидация как сейчас: пары 1–12, `HH:MM`, без пересечений.

**Не входит.** UI редактора (R-16), подстановка в карточки пар (R-17).

**Готово когда.** `GET /api/bells?date=` отдаёт полную картину для Москвы на эту дату, включая кураторский час если он включён.

**Зависит от.** R-02, R-03 (дата Москвы).

---

### R-16. Редактор звонков пишет только API

**Зачем.** Debounce 400 мс в `melmk_bells_v2`; `PUT /api/admin/bells` из раздела «Звонки» не вызывается.

**Сделать.** Четыре карточки + куратор + сокращённые даты → серверные ручки. Убрать localStorage как источник правды. После сохранения другие устройства видят сетку после следующего GET.

**Не входит.** Перенос исторических значений с одного админского телефона (можно один раз мигрировать вручную дефолтами МелМК).

**Готово когда.** Правка понедельника на одном компьютере видна студентам и второму админу.

**Зависит от.** R-15, R-05.

---

### R-17. Публичный UI берёт звонки с сервера

**Зачем.** `getPairTimesForDay` дублирует сетки для `start`/`end` у уроков с API. Short-даты сервера публичный экран сам не перечисляет.

**Сделать.** Виджет «Сейчас», вкладка «Звонки», карточки пар — слоты из API (R-03 + R-15). Локальный `BellsConfig` не задаёт институтские часы. Кэш — для офлайна (P6), не вторая истина.

**Не входит.** Service Worker.

**Готово когда.** Сокращённый день, заведённый в админке, меняет таймер у студента без правки LS.

**Зависит от.** R-15, R-03.

## P5. Админка без второго локального мира

После P3–P4 большая часть «локального мира» уже должна умереть. Здесь остаток, который иначе снова разъедется.

### R-18. Замены диапазоном — одна операция API

**Зачем.** Мастер пишет `scheduleData.substitutions` и пачку `PUT` по датам (до 16 недель / 120 дней). Частичный сбой не откатывает уже записанное. Без сессии мастер врёт, что замена «сохранена» в браузере.

**Сделать.** Один запрос: группа, пара, правило дат, payload пары или отмена. Сервер раскрывает даты, пишет overrides транзакцией, возвращает список дат и ошибки. Локальный массив — не журнал истины (истина — R-09 + выборка overrides).

**Не входит.** Право преподавателя менять свои пары.

**Готово когда.** 16 недель либо все записались, либо ни одна; админ видит отчёт.

**Зависит от.** R-05, R-03.

---

### R-19. Справочники кабинетов и преподавателей на сервере

**Зачем.** Разделы `#teachers` / `#rooms` правят кэш. После sync побеждает API. Upload Excel пересобирает справочники из ячеек и затирает ручные имена.

**Сделать.** CRUD `rooms` / `teachers` под admin. Импорт Excel **сливает** имена, не обязательно удаляет ручные (явно: не трогать / пересобрать). Кабинет преподавателя (R-07) смотрит на id/канон из этой таблицы.

**Не входит.** Нагрузка аудиторий, конфликты «два преподавателя в одном кабинете» как продукт.

**Готово когда.** Добавленный вручную преподаватель переживает импорт в режиме «не затирать»; его можно привязать к учётке.

**Зависит от.** R-05, R-12 (знать момент импорта).

---

### R-20. Вычистить локальные истины админки

**Зачем.** Иначе через месяц снова появятся «черновик только здесь», второй Excel, audit в LS.

**Сделать.** Пройти админку чеклистом: каждый раздел читает/пишет API. Нет скрытого `parser/` для сетки, нет `substitutions[]` как хранилища замен, нет `melmk_bells_v2` как канона, нет `melmk_audit_v1` как канона. IndexedDB — кэш того же API, что у публичного сайта.

**Не входит.** Новый UX с нуля, объединение двух HTML в один бандл ради чистоты.

**Готово когда.** Чистый профиль браузера + сессия admin = полная админка; второй браузер без сюрпризов.

**Зависит от.** R-14, R-16, R-18, R-19, R-09.

## P6. Офлайн PWA

Зачатки есть (`frontend/sw.js`, IndexedDB, manifest), результата «открыл в подвале колледжа последнее расписание» нет: SW режет `/api/` как network-only, список ассетов неполный, hydrate дней требует сеть.

### R-21. Shell и стратегия SW

**Сделать.** Precache всех скриптов/стилей публичного UI (включая mood CSS и недостающие модули). Навигация: offline shell. API: не «всегда сеть», а согласованная схема с R-22 (например network-first с fallback на кэш ответа или клиент сам читает IDB и SW не мешает). Версия кэша не ломает установку на iPhone бесконечным skipWaiting без UI.

**Не входит.** Админка офлайн (не цель). Push.

**Готово когда.** Airplane mode после визита: HTML/CSS/JS приложения открываются, белого экрана из-за незакэшированного модуля нет.

**Зависит от.** — можно начинать параллельно, но не считать закрытым до R-22.

---

### R-22. Снимок данных в IndexedDB

**Сделать.** Хранить: список групп, шаблон выбранной (лучше всех уже скачанных) группы, слитые дни, которые пользователь уже видел, звонки, revision с сервера. Стартовый путь: прочитать снимок → нарисовать → если сеть есть, обновить (offline-first). Не затирать удачный снимок пустым ответом при ошибке сети.

**Не входит.** Редактирование офлайн с очередью мутаций (админ всегда online).

**Готово когда.** После синка выбранной группы выключение сети оставляет день/неделю/месяц и вкладку звонков с **последними известными** заменами для уже открытых дат. Неоткрытый месяц может быть неполным — это допустимо и должно быть видно.

**Зависит от.** R-03, R-17.

---

### R-23. Поведение офлайн в UI

**Сделать.** Явный статус: офлайн / «обновлено в …» / ошибка синка. Не спиннер навечно. Кнопка обновить не уничтожает кэш при неудаче. Пустой экран только если снимка правда нет.

**Готово когда.** Студент понимает, что смотрит кэш, а не «сайт сломался».

**Зависит от.** R-22.

---

### R-24. Установка на домашний экран iPhone

**Сделать.** Проверить манифест, иконки 180/192/512, `display`, HTTPS, SW в корне scope Safari, отсутствие требования до установки, которого Safari не выполняет. Короткий процесс для админа: «как поставить студентам». Админка в PWA не обязательна.

**Готово когда.** С Safari на iOS «На экран Домой» открывает приложение без адресной строки и с последним снимком (R-22).

**Зависит от.** R-21.
