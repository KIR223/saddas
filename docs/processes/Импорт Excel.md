# Импорт Excel

Канонический путь семестра на всех устройствах — `POST /api/admin/upload`. Парсер: `backend/app/parser.py`. Кнопка в админке: раздел «Данные», `handleExcelFile` в `frontend/admin/admin-app.js`.

## Зачем

Официальная сетка пар живёт в Excel. Система не редактирует шаблон «навсегда» через форму: смена семестра = новый файл. Правки отдельных дат — отдельный процесс [[processes/Замены]].

## Канонический поток (есть токен API)

1. Администратор открывает `/admin/` → «Данные», сохраняет `x-admin-token`.
2. «Загрузить Excel», файл `.xlsx`.
3. `uploadAndSync`: multipart на API, затем полная выгрузка всех групп (`syncFullFromApi`).
4. Сервер проверяет токен, расширение, размер ≤ 20 МБ.
5. `parse_workbook` по всем листам. Если занятий 0 — 400, в `detail.warnings` листы без групп.
6. `replace_schedule`: новые `lessons` (ФИО и кабинеты канонизируются так же, как справочник), пересобранные `rooms`/`teachers`, `meta.filename` / `uploaded_at` / `title` (`revision` в API — то же значение).
7. **Не трогаются:** `lesson_overrides`, таблицы звонков.

Ответ upload: число групп, записей занятий, кабинетов, преподавателей, предупреждения.

## Как читается таблица

Ожидаемый вид листа (как в колледже):

- Вверху строка с кодами групп (`ТМ-261`). Объединённая ячейка группы: левый столбец — предмет и преподаватель, правый — аудитория. Правый столбец с тем же кодом группы не считается второй группой.
- Левее первой группы — день недели (текст содержит «понедельник» …) и номер пары 1–12. Номер пары часто на двух строках.
- В ячейке занятия: первая непустая строка — предмет, остальные — преподаватель.
- Аудитория: `321`, `321А`, `с/з` / `С/З`, несколько через запятую.

### Цвет = неделя

| Заливка ячейки предмета | Записи в БД |
| --- | --- |
| Зелёная | только `week=green` |
| Красная / розовая | только `week=red` |
| Нет заливки, серая, почти серая (разброс RGB < 18) | две записи, green и red |
| Одна объединённая ячейка на обе строки пары | цвет origin-ячейки решает одну неделю или обе |

Порог серого специально низкий: бледно-зелёный Excel `(226, 240, 217)` должен остаться зелёным, не «нейтральным».

Без цветных заливок на двух строках пары парсер считает это одним занятием на обе недели: предмет сверху, преподаватель снизу (`combine_both_weeks`).

Заголовок семестра: первая ячейка в углу листа, где в тексте есть «расписан».

## Локальный импорт (нет токена)

Админка принимает `.xlsx`, `.xls`, `.csv`. Без токена:

1. `parseFile` (SheetJS, может грузиться с CDN).
2. `autoMap` + `rowsToSchedule` — другая модель колонок, не `parser.py`.
3. Результат пишется в IndexedDB этого браузера. Сервер и другие студенты файл не видят.

Импорт JSON в том же разделе заменяет локальный `ScheduleData`, если есть поле `groups`. Это откат/перенос кэша, не загрузка в SQLite.

Экспорт JSON/CSV/ICS/печать выгружает **локальный снимок**, не дамп БД.

## После импорта

Публичная страница подхватит новый шаблон после обновления (кнопка) или следующего bootstrap. Старые day-overrides продолжают накладываться на новые пары с теми же номерами: если сетка семестра сильно изменилась, замены могут стать бессмысленными — их нужно снять вручную (`DELETE` дня/пары).

## Импорт в ручную модель (R-12)

POST /api/admin/upload требует сессию admin. Поле mode=replace заменяет весь шаблон lessons; mode=missing добавляет только группы, которых ещё нет в groups. Существующие ручные группы сохраняются. Ответ diff: groups_created, lessons_created, lessons_removed, mode. Парсер заливок остаётся серверным openpyxl.
